# Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `make up` fails with "port is already allocated" | Something else uses 5610, 5625, 5630, 5642, 5650, 5666 or 5679 (or 5635 for `make test-integration`, 5696 for `make tf-aws-on-floci`) | Set the matching `TESTFORGE_*_PORT` in `deploy/compose/.env` ([configuration.md](configuration.md#local-stack-deploycomposeenv)) and run `make up` again |
| Compose says "run `make env` first" | `deploy/compose/.env` is missing a secret | `make env` (it never overwrites an existing file; delete it to regenerate, then `make down` so the database matches) |
| Building the sandbox image sits for a long time at `apt-get install` | A slow route to `deb.debian.org` (the default CDN) | Set `TESTFORGE_APT_MIRROR` to a faster official mirror that also serves `-security`, for example `TESTFORGE_APT_MIRROR=http://ftp.de.debian.org/debian` in `deploy/compose/.env`, then `make up` (or `make build`, `make test-sandbox`). Empty keeps the default mirror |
| Building the sandbox image stops at `git clone` of nsjail or at `npm ci` | GitHub or the npm registry unreachable or slow | Retry: nsjail is a pinned tag and `npm ci` retries with backoff; both are cached by Docker after the first success |
| Every run ends as `error` with "The sandbox could not start the run (nsjail failed)" | The sandbox runs without its seccomp profile, or the host forbids unprivileged user namespaces | Use the Compose service as is (it sets `seccomp=infra/docker/sandbox-seccomp.json`). On a Linux host check `sysctl kernel.unprivileged_userns_clone` (Debian, older Ubuntu) and `kernel.apparmor_restrict_unprivileged_userns` (Ubuntu 24.04 and later) |
| Runs stay `queued` | The worker is not running, or every sandbox slot is busy | `make ps`, `make logs SERVICE=worker`; `sandbox failure` lines with `reason` `busy` mean add sandbox replicas, `unreachable` means the sandbox is down ([operations.md](operations.md)) |
| A run ends as `limit_exceeded` | The tests crossed the run's CPU, memory, output, process or wall clock limit. The message names it, and the test that was running when it hit is listed as an error naming the limit, while finished tests keep their results | If the suite legitimately needs more, raise the project's limits in its settings (up to the instance ceilings, `RUN_*_CEILING_*`). A test that sleeps on a socket or waits for a service will never finish: the sandbox has no network |
| A run ends as `error`: "The run finished without running any test" | No test was found or collected: test files not matching `test_*.py`, `*_test.py`, `*.test.*` or `*.spec.*`, or a `generated` run with no accepted tests in that language | Check the file names; for generated tests, accept some first |
| Tests fail to import a library (`ModuleNotFoundError`, "Cannot find package") | Runs never install anything: they have no network. Only the toolchain's libraries (pytest, coverage, FastAPI, httpx, Pydantic, Flask, requests; Vitest) are available | Add the library to `sandbox/toolchain/python/requirements.txt` or `toolchain/js/package.json` and rebuild the sandbox image |
| Generation reports tests refused | The assertion check refused them: `no_assertion` (no real assertion that can run), `not_grounded` (never calls the code under test), `syntax_error`, `no_tests`. Each refusal keeps its name and reason on the generation | Nothing to fix on TestForge's side: the refused tests were placeholders. Regenerate with extra instructions, use a stronger model, or document the unit (examples, raise conditions) so there are facts to assert ([generation.md](../architecture/generation.md)) |
| Generation fails with `bad_answer` | The model did not answer with the JSON object the prompt asks for | Try again, or a model that follows instructions better; the provider's connection test in settings checks the basics |
| API test generation says it needs an app | Analysis found no `app = FastAPI()` or `app = Flask(...)` at module level in the import | API tests drive the application object in process; expose one at module level |
| Importing a GitHub repository fails with "GitHub has no such repository, ref or pull request (or it is private: add a token)" | GitHub answers 404, not 403, for a private repository requested without a token; or the name or ref is wrong | Add a token with read access to contents and pull requests in the project's settings, check `owner/name` and the ref |
| "GitHub refused the request: the repository is private or the token lacks access" | 401 or 403: the token is wrong, expired or lacks scopes | Replace the token |
| Local imports of real repositories go to the demo's mock | Compose points `GITHUB_API_URL` at the mock GitHub | Set `TESTFORGE_GITHUB_API_URL=https://api.github.com` in `deploy/compose/.env` and `make up` |
| "The configured GitHub API address is not allowed" | `GITHUB_API_URL` resolves to a private or metadata address and `GITHUB_ALLOW_PRIVATE` is false | For GitHub Enterprise inside your network set `GITHUB_ALLOW_PRIVATE=true`; metadata addresses are always refused |
| A webhook delivery stays failed with "resolves to a private or metadata address" | The receiver is on a private network | Set `WEBHOOK_ALLOW_PRIVATE=true` for receivers inside your network |
| The upload is refused as too large | Over `MAX_UPLOAD_BYTES` (25 MB), or the snapshot over `MAX_SNAPSHOT_BYTES` or `MAX_SNAPSHOT_FILES` | Leave dependencies, build output and data files out of the ZIP (they are skipped anyway), or raise the limits |
| 429 "Too many generations" or runs | `GENERATE_RPM` or `RUN_RPM` per project | Wait for `Retry-After`, or raise the limit |
| The API refuses to start with "unsafe production configuration" | `ENVIRONMENT=production` with demo or weak secrets, equal secrets, `COOKIE_SECURE` off, `MAIL_BACKEND=log`, `STORAGE=local` or an endpoint override | Fix each item the message lists ([configuration.md](configuration.md)) |
| Member notices are not received locally | Mail goes to Mailpit, not the internet | Open http://localhost:5625 |
