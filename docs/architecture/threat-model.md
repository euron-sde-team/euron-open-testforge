# Threat model

The attacks considered, what stops each, and what is left. STRIDE-style; the controls are
described in [security.md](security.md) and [sandbox.md](sandbox.md).

| # | Threat | Actor | Mitigation | Residual risk |
| --- | --- | --- | --- | --- |
| T1 | A run reaches the network: exfiltrates source, calls an internal service, the database or the cloud metadata endpoint | Uploaded project, generated test, a malicious dependency in the snapshot | Fresh network namespace per run (loopback only, no route); the sandbox container on an internal network shared with the worker alone (Compose) or a security group with no egress (AWS); IMDSv2 hop limit 1 and blocked task metadata | None known; proved by the sandbox suite and the "Sandbox checks" demo project |
| T2 | A run reads the platform's credentials, the service's code or another project's files | Same | Mount namespace with read-only system directories and toolchain, its own workspace and a private `/tmp` only; no `/proc`, `/etc/passwd`, `/opt/venv` or other workspace; an environment built from scratch; one run per process | None known |
| T3 | A run escapes the jail | Anyone who can import code or generate tests | User, PID, network, mount, IPC and UTS namespaces; a kafel filter refusing namespace, mount, ptrace, bpf, keyring, perf and io_uring calls; an unprivileged container with every capability dropped and a read-only root | Kernel vulnerabilities reachable through user namespaces. For open uploads, add gVisor, Kata, microVMs or dedicated hosts |
| T4 | An escaped run reaches data or cloud credentials | Attacker after T3 | The sandbox holds only `SANDBOX_SECRET`; its network reaches nothing; its task role has no policy | The signing secret lets it start and stop sandbox runs, nothing more. Rotate it after any suspected escape |
| T5 | A run makes the service return a file it should not (a report replaced by a symlink to a secret) | Generated test, uploaded project | Results read with `O_NOFOLLOW` per path component, regular files only, size caps; stdout and stderr are files outside the jail | None known |
| T6 | A run exhausts the machine: CPU, memory, fork bomb, output flood, sleeping forever | Same, or an honest bug | rlimits (CPU, address space, processes, file size, open files, stack), nsjail wall clock, a backstop timer, `oom_score_adj` 1000, the container's own CPU, memory and pids limits; the run stopped and named by the limit | A Node run can briefly exceed its memory limit before the check (bounded by the container limit) |
| T7 | A crafted archive writes outside its folder or exhausts memory while unpacking | Uploader, a malicious repository | Unpacked into memory, never to disk; absolute paths, `..`, links and devices skipped; file count, file size and total size capped while reading | None known |
| T8 | Importing a repository runs its code (git hooks, install scripts, build steps) | Malicious repository | GitHub tarball of one commit, no clone, nothing executed; analysis parses only | None known |
| T9 | A forged or replayed request starts a run on the sandbox | Anything on the sandbox network | HMAC over timestamp and body with `SANDBOX_SECRET`, five minutes of skew, compared in constant time; the network admits only the worker | A captured request can be replayed within five minutes, from inside the sandbox network only; it reruns the same workspace |
| T10 | A test that cannot fail is shown as coverage of real behaviour | A careless or adversarial model | The assertion check refuses placeholders, unreachable assertions and tests that never call the code; refusals are counted and shown; tests arrive as proposed until a person accepts them | The check cannot tell whether an expected value is right; the person reviewing and the failure explanation cover that |
| T11 | A member of one organization reads or changes another's projects, tests or runs | Signed-in user, API key holder | `Principal` resolved on every project route, queries filtered by project, 404 for anything not visible, keys bound to one project, scopes checked | Organization owners and admins see every project in their organization by design |
| T12 | Account takeover by password guessing | Outsider | Argon2id, per-IP throttle, per-account lockout in Postgres | Lockout can be used to annoy a known account for 15 minutes |
| T13 | CSRF against a signed-in editor (start runs, accept tests) | Malicious site | Custom header on cookie mutations, CORS allowlist, HttpOnly cookie | None known |
| T14 | A configured URL is used for SSRF (provider base URL, GitHub API URL, webhook URL) | Project admin | Resolved at call time; metadata addresses always refused in every spelling; private addresses refused for GitHub and webhooks unless allowed; no redirects followed | Admins may point providers at private addresses by design (`PROVIDER_ALLOW_PRIVATE`) |
| T15 | A forged GitHub webhook imports arbitrary pull requests | Outsider | `X-Hub-Signature-256` with the project's sealed secret; unknown project and bad signature answer the same 401 | None known |
| T16 | Stolen secrets from a database dump | Attacker with the database | Provider keys, GitHub tokens and webhook secrets sealed (AES-GCM or KMS) with a record-bound context; API keys stored as peppered HMACs; passwords as argon2id | With `KEY_MODE=local`, a dump plus `LOCAL_MASTER_KEY` opens the sealed values: use KMS in production |
| T17 | Source code leaks to a model provider | Provider | Mock provider by default in the demo; any provider per project, including local ones; only the units being tested (signature, docs, source excerpt) are sent | With a hosted model, that source leaves the network: choose a local model where it matters |
| T18 | A job is lost, run twice, or recorded by a worker that lost it | Failure, not an attacker | Postgres queue with leases, renewals, a reaper and compare-and-set finishes on `lease_owner`; the job row is written with its record | A run cut short by a lost lease is run again from the start |
| T19 | Spreadsheet formula injection from test names or messages in a CSV report | Model output, uploaded test names | Leading `=`, `+`, `-`, `@`, tab and carriage return neutralised | None known |
| T20 | Script in an HTML report runs in the app's origin | Model output, uploaded test names | The download carries a CSP with `sandbox` and `default-src 'none'` | None known |
| T21 | The audit trail is altered to hide what ran | Insider with database access through the app | Append-only by trigger; retention never deletes it | A database superuser can drop the trigger: protect database credentials |
| T22 | Denial of service through large uploads or many generations and runs | Outsider, abusive member | Bodies capped before parsing; large bodies only on the upload route with a session or key; per-project rate limits; the queue absorbs bursts | Volumetric attacks are for the load balancer and WAF |
